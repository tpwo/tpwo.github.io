I was a Windows user whole my life but a few years ago I switched to MacOS, and I really like this transition.

I remember that beginnings were difficult, as many things are way different on these systems. You can tweak some things around for it to feel more natural but I prefer having as little of that as possible.

IMO it doesn’t make sense to try convert MacOS into Windows as it would be just a worse copy. Instead it’s better to change some habits.

Keyboard and mouse

Coming from Windows, Some macOS defaults are quite weird for a Windows user, so I think that some of them can be tweaked slightly, to have more familiar experience.

Enable tap to click

By default to have actual click with the trackpad, you have to press it until it clicks. But with the mentioned option enabled the tap is enough.

You can find Tap to click option in Trackpad settings.

Invert scroll

I’m used to a way of scrolling where I scroll down, and the content also scrolls down.

The inverse of that is default in MacOS. At first, I thought it’s impossible to change it, but it turned out the option is there, but it has a weird name: natural scrolling, where "content tracks finger movement". It’s hidden in Trackpad settings under Scroll & Zoom settings.

That’s true, but in my opinion it makes more sense when using touch screen, where you have a direct connection between fingers and the content.

Even if I’m on someone’s else machine, changing this is one click. Also, this isn’t a big blocker, just a small annoyance.

Remap action keys

I’m an avid terminal, tmux, and nvim user, so I use Ctrl key a lot. On all of my machines I remap CapsLock key to Control[1], as CapsLock is almost never used, and can be easily replaced by pressing Shift. And at the same time, it’s located in the home row, which means it’s very easy to reach.

On Windows I had to use a separate tool called Ctrl2Cap (although written by a Microsoft employee).

On MacOS, you can do the remap directly in the OS, for at least few years. I’m doing the same CapsLock → Control remapping.

Remapping keys on Windows-type keyboard

Important:

I tried remapping Windows keyboard but then gave up. It’s easier to use native MacOS keyboard. Or at least, a keyboard built to be compatible with MacOS. I’m leaving below notes as it might be helpful to someone.

I quickly learnt that Windows and Mac keyboards are way different than you may think. Especially when talking about action keys.

The problem is that MacOS has one more action key that Windows: Command key. Some of the functionality I was used to do with Ctrl or Alt is now done with Command.

I understand it like that:

  • Fn key is the same as Fn in Windows (most commonly laptops)
  • Windows Alt is either an Option key[2]. (e.g. when typing special diacritic characters) or a Command key (Command+Tab is Alt+Tab from Windows)
  • But Command key also sometimes acts as a Windows Control (e.g. in Chrome, closing tab is Command+W)
Note: Remapping Windows keyboards

I found a recommendation to remap Alt on Windows keyboard to Command key and remap Windows Key to Option key. This makes Alt+Tab etc. to work like on Windows, but definitely is not ideal.

Namely, I never figured out how to properly approach typing of Polish characters when using a remapped Windows keyboard. By default on Mac it’s done with an Option which should be fine, if I haven’t done the remapping described above. After the remap I can only type in Polish characters with the Windows key, but there is only one of them, and it’s on the wrong side of space key.

There are solutions to remap keys more dynamically, like Karabiner (similar to Windows AutoHotkey) but this complicates things a lot.

I end up using a Mac keyboard, so I never had the time to find a proper solution here.

Adjust key repeat rate and delay until repeat

Compared to Windows, macOS waits longer before it starts repeating keys. so I change the delay to be as short as possible to get a more familiar experience.

I also like the fastest key repeat rate setting although it’s definitely faster than on Windows. You may want using a bit slower option but still consider making it faster than the default.

Disable macOS accent picker

By default when pressing and holding certain keys in MacOS, system displays a window allowing you to choose an accent for a given letter (e.g. for a, e or o).

This also completely blocks key repeat mentioned above. It’s not active in all apps but annoys me a lot, so I always disable it.

Tip:

I noticed this feature in VS Code when Vim bindings plugin wasn’t working properly. Initially I thought that something is wrong with VS Code or my installed plugins…​

Running this command disables it system-wide:

defaults write -g ApplePressAndHoldEnabled -bool false

It’s also possible to disable/enable it per application but I haven’t tested it.

Package manager

MacOS doesn’t come with a native package manager installed. There is the App Store, but you won’t find everything there, and I find myself rarely using it.

There are some options to choose from on MacOS but Homebrew is definitely the most popular one.

It has some issues, and I heard some people complaining on it. They were mainly talking about brew breaking their tools when doing upgrades.

To avoid that, don’t run brew upgrade without any arguments. It will update versions of all apps installed with it which may be a lot of changes.

Prefer brew upgrade <name>. brew outdated shows you the list of outdated apps. It’s updated along with the brew itself when running brew update.

Tip:

You can disable annoying auto-updates of brew which often occur when you do brew install or brew upgrade by setting HOMEBREW_NO_AUTO_UPDATE=1.

Recently I started installing some tools outside brew, especially tools with auto-update option built-in, e.g. uv or claude code. I noticed that they usually recommend the native installation instead of relying on a package manager.

There are also some solutions like asdf which allow to keep many versions of the same tool, and dynamically swap them depending on the project. I would still advocate to use them as an addition to brew rather than its replacement.

Formuleas vs. casks

Homebrew has at two types of installations: formulaes and casks. Formuleas are typically for open source CLI tools and libraries. They are installed with the standard brew install <recipe-name>.

Cask is a recipe type for installing GUI apps. Usually it involves downloading the app packaged in dmg or zip format. Both open and closed source software is distributed this way. Casks are installed via providing additional flag: brew install --cask <recipe-name>. Usually you have to provide your password to install the cask app, as the installation requires moving the app into the Applications folder.

You can include --no-quarantine flag to avoid additional prompt before first time running of the cask app.

Updates

Homebrew offers updates, and only formulaes are updated by default. This is because a lot of cask apps offer their own auto-update mechanism. Each cask recipe has a flag which tells Homebrew if this is the case. You can force the update of these apps, but in practice it works like removing and installing the app from scratch, so you might lose some configuration etc.

Add brew to PATH

By default, Homebrew is installed in /opt/homebrew. brew binary is located at /opt/homebrew/bin folder, and all other formulaes are there. You need to add it to PATH.

Change default shell

MacOS switched from Bash to zsh a few years ago. I use Bash on my every other system, and I didn’t want to learn a new shell just for one platform. Migrating from Bash to zsh on other platform is impractical, as Bash is the de facto standard in the industry when talking about Linux platforms.

Install newest Bash

Before doing that install the newest Bash: brew install bash.

Bash version shiped with MacOS is a pretty old 3.2. The newest version is 5.X, and running on 3.2 caused issues with my dotfiles (namely globstar shell option missing in 3.2). I read that Apple includes older version due to licensing, as Bash project migrated to a less permisive license with v4.

Run chsh

There is a chsh command which changes your shell with a single command.

Before that you have to add newly installed Bash which is located by default in /opt/homebrew/bin/bash to /etc/shells which requires root permissions. And then you can run the command:

chsh -s /opt/homebrew/bin/bash

Useful apps & extensions

Install bash completions

After you install Bash, you will quickly notice that tab completions are missing. Fortunately, homebrew has a recipe to install them. When using newer Bash v5, you have to install @2 version of the recipe.

brew install bash-completion@2

Then, you have to source downloaded file in your .bashrc. For that, I use a little utility function which does -r on the path (checks if a file is readable) before sourcing it.

_source_if() { test -r "$1" && . "$1"; }

_source_if '/opt/homebrew/opt/bash-completion@2/etc/profile.d/bash_completion.sh'

Remember that you can use brew --prefix bash-completion@2 to always get the correct path regardless of brew install location. I decided to use hardcoded path, as running brew --prefix takes some time to execute, when you add it to your .bashrc.

Install Git completions

I noticed that Git installed in Mac doesn’t ship with tab completion. I read something about it, I noticed it, as my $PS1 uses __git_ps1 which wasn’t available.

I found that you can download the completions file manually.

mkdir -p ~/.local/completions
curl https://raw.githubusercontent.com/git/git/master/contrib/completion/git-completion.bash \
  -o ~/.local/completions/

In your .bashrc:

_source_if "$HOME/.local/completions/.git-completion.bash"
Note:

This is not an ideal solution, as it freezes the version of Git completions. But Git is a stable program, so I guess it’s good enough.

Install iterm2

brew install --cask iterm2

Default terminal in MacOS is similar to Windows, I mean: it’s not so great. Even before switching to Mac I heard about iterm, and this is the alternative I chose.

Swich from BSD to GNU utils

After importing my dotfiles, I quickly noticed that there are some issues with Unix tools. Namely ls --group-directories-first was a problem. It turns out BSD ls doesn’t have this flag.

I was aware about big differences in other tools like sed, but I didn’t know that even ls is impacted.

Later I also noticed that BSD xargs doesn’t support --delimiter flag, so there are a lot of small annoyances.

Fortunately, you can install missing utils via brew, and prepend them to your PATH, so they take precedence.

brew install coreutils
brew install findutils
brew install gnu-sed

Then you can use brew --prefix coreutils to see where the binaries were downloaded.

In fact, they are a bit hidden in subfolders:

/opt/homebrew/opt/coreutils/libexec/gnubin
/opt/homebrew/opt/findutils/libexec/gnubin
/opt/homebrew/opt/gnu-sed/libexec/gnubin

Add them in the beginning of your PATH and you should be good to go.

I’ll share a little convenient function I use in my .bashrc to do this easily. It tests if a given folder exists before adding it, so you can leave it also on other platforms if you share your dotfiles between machines.

,pathprepend() {
  for arg in "$@"; do
    test -d "$arg" || continue
    PATH=${PATH//:"$arg:"/:}
    PATH=${PATH/#"$arg:"/}
    PATH=${PATH/%":$arg"/}
    export PATH="$arg${PATH:+":${PATH}"}"
  done
} && export -f ,pathprepend

# Remember that the last arg will be first in PATH
,pathprepend \
  "$HOME/.local/bin" \
  <...> \  # other entries here
  "/usr/local/opt/coreutils/libexec/gnubin" \
  "/usr/local/opt/findutils/libexec/gnubin" \
  :

Mole

brew install mole

Theoretically, uninstalling an app in MacOS is just moving it to the trash. I quickly found out that life isn’t so simple in practice. In fact, a lot of apps is not fully uninstalled, leaving configuration files or cache behind. It’s very annoying when you’re trying to do a clean reinstall, and these leftovers clutter your disk space.

Mole can help both with uninstalling apps cleanly, always showing you different places where a certain app has its files (allowing you to select how clean the uninstall should be), but it can also help you remove old leftovers or cache from apps like docker, npm or uv. If you’re struggling with free space on your Mac, I really recommend it.

Install Doll

brew install --cask doll

MacOS doesn’t have any native support for tray icons for apps. The only way to have a tray icon is for the app to define it.

I was surprised to see that most apps don’t have them defined, e.g. Slack or Teams. Coming from Windows this was a big difference, but fortunately I found and app called Doll which is able to handle that.

Install Sublime Text

brew install --cask sublime-text

On Windows I got used to Notepad+\+, and I wanted something with a similar feel. I tried CotEditor, as recommended to be MacOS-native editor, but I didn’t like it very much. Sublime Text was the answer. It can be installed via homebrew, it supports tabs, and works quite well with a lot of configuration options.

To open all files in the same window of Sublime Text, you have to change a config option, as by default it always opens a new window. You have to set:

"open_files_in_new_window": "never",

By looking at the default config, it seems that it’s already set, but for MacOS it’s overwritten to a different option.

Set a default text editor

It turns out it’s more compilcated than you might think, especially if you want to open all text files this way (i.e. you don’t care about their extensions). I found out that installing duti is the simplest option for me:

brew install duti

duti -s com.sublimetext.4 public.plain-text all
duti -s com.sublimetext.4 public.data all

This way, you don’t have to override the default editor for each file extension one-by-one which is a blessing.

Install uv for Python ecosystem integration

brew install uv

I noticed that uv can be a good choice on MacOS, as it supports installing a lot of Python versions with a single command.

I noticed that you can symlink installed Python versions, so they are correctly detected by tools like tox.

ln -s /Users/twojdat/.local/share/uv/python/cpython-3.12.7-macos-x86_64-none/bin/python3.12 ~/.local/bin/

If you want to change the default version of Python, also symlink python3 binary.

All of that works granted you have ~/.local/bin added to your PATH.

Enable sudo auth with Touch ID

Touch ID is great, as it uses your fingerprint to quickly authorize certain actions. It turns out, sudo can also make use of it. The basic configuration is very simple: go to /etc/pam.d/sudo_local file (you’ll need sudo for that 😅), and uncomment the line:

auth  sufficient  pam_tid.so

That’s it, the next time you run sudo, it’ll ask you for Touch ID, and you can optionally type in password.

I’m an avid tmux user, so I had to install additional dependency, to make it work also in tmux:

brew install pam-reattach

Then you have add the new line in sudo_local file:

auth  optional  /opt/homebrew/lib/pam/pam_reattach.so  ignore_ssh

As you can see, you have to provider the full path to pam_reattach.so. ignore_ssh option is used to help mitiage some edge cases, and I took it from this tutorial.
